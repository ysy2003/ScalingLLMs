Reorganising a Consul key-value store

Published on October 27, 2023

The Challenge of a Growing KV Store

As systems evolve, so does the data they manage. In HashiCorp Consul, the key-value (KV) store is a flexible tool for dynamic configuration, feature flags, and service discovery. However, without a clear strategy, it can quickly become a disorganized collection of keys, making maintenance and discovery difficult. This was the exact problem we faced: our initial, flat key structure was no longer scaling with our services.

Our Approach: A Three-Step Migration

We decided on a structured migration process to reorganize our keys into a more hierarchical and predictable format. The goal was to move from a flat structure like service-a-db-url to a nested one like services/service-a/config/db_url. This approach involved exporting, transforming, and re-importing the data.

Step 1: Exporting the Existing Data

The first step is to create a complete backup of the current KV store. Consul's CLI provides a simple way to export all keys and their values into a JSON file. This ensures we have a safe rollback point.

consul kv export > consul-kv-backup.json

This command dumps the entire KV store into a JSON array, where each object contains a key, flags, and a base64-encoded value.

Step 2: Transforming the Keys with a Script

With the data exported, we can now manipulate it offline. We wrote a small Python script to read the JSON backup, iterate through each item, and create a new key based on our desired structure. For example, a key like auth_service_timeout would be transformed into services/auth/config/timeout.

# transform_keys.py
import json
import base64

with open('consul-kv-backup.json', 'r') as f:
    data = json.load(f)

transformed_data = []
for item in data:
    # Example transformation logic
    old_key = item['key']
    if old_key.startswith('legacy_prefix/'):
        new_key = old_key.replace('legacy_prefix/', 'new_prefix/v1/', 1)
        item['key'] = new_key
        transformed_data.append(item)

with open('transformed-data.json', 'w') as f:
    json.dump(transformed_data, f, indent=2)

print("Transformation complete!")

This script generates a new JSON file, transformed-data.json, containing the reorganized key structure while preserving the original values.

Step 3: Importing the New Structure

The final step is to import the transformed data back into Consul. The consul kv import command can read the JSON file and populate the KV store. It's often wise to import into a new path (e.g., staging/) first to verify everything works as expected before replacing production data.

consul kv import @transformed-data.json

After verifying the new structure, we could safely delete the old keys and update our applications to point to the new, organized paths.

Conclusion

Reorganizing a live Consul KV store can seem daunting, but with a careful export-transform-import process, it can be done safely and efficiently. The result is a more maintainable, scalable, and understandable configuration system that will serve our teams better in the long run. Proper organization is not just an aesthetic choice; it's a critical part of operational excellence.
